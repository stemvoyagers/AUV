# AUV Simulator — ground truth and synthetic sensor data

Python simulator that produces the **ground truth** and the **synthetic sensor
measurements** used to develop and test the AUV navigation software. It does not
implement navigation; it generates the data a navigation filter is measured against.

---

## 1. Scope

In scope:

- a consistent ground-truth state for the vehicle,
- the agreed 120-second scenario,
- a configurable simulation clock,
- ideal and corrupted readings for accelerometer, gyroscope, magnetometer and pressure,
- CSV export of everything a navigation filter needs,
- plots and automated tests.

## 3. Scenario

| Stage | Time (s) | Motion |
|-------|----------|--------|
| 0 | 0–10 | stationary at 20 m, heading north |
| 1 | 10–20 | smooth acceleration to 0.8 m/s |
| 2 | 20–35 | constant 0.8 m/s north |
| 3 | 35–65 | smooth 90° turn towards the east |
| 4 | 65–75 | constant 0.8 m/s east |
| 5 | 75–105 | descent from 20 m to 24 m while travelling east |
| 6 | 105–120 | constant 0.8 m/s at 24 m |

The resulting checkpoints (dt = 5 ms):

| t (s) | north (m) | east (m) | depth (m) | heading | speed (m/s) |
|-------|-----------|----------|-----------|---------|-------------|
| 0 | 0.000 | 0.000 | 20.000 | 0° | 0.000 |
| 20 | 4.000 | 0.000 | 20.000 | 0° | 0.800 |
| 35 | 16.000 | 0.000 | 20.000 | 0° | 0.800 |
| 65 | 31.279 | 15.279 | 20.000 | 90° | 0.800 |
| 75 | 31.279 | 23.279 | 20.000 | 90° | 0.800 |
| 105 | 31.279 | 47.279 | 24.000 | 90° | 0.800 |
| 120 | 31.279 | 59.279 | 24.000 | 90° | 0.800 |

**20 m is a scenario parameter, not a rule.** The trajectory takes
`initial_depth`:

```python
from auv_simulator import Trajectory

trajectory = Trajectory(initial_depth=20.0)   # default
```

The final depth is always `initial_depth + 4.0 m`.

### Why the motion is smooth

- **Acceleration (10–20 s)** uses a smootherstep velocity profile, so acceleration
  and jerk are zero at both ends. The vehicle covers 4 m and leaves the stage at
  exactly 0.8 m/s with no acceleration step.
- **Turn (35–65 s)** is a coordinated constant-yaw-rate arc: 90° over 30 s, i.e.
  3°/s and a 15.28 m radius, with speed constant.
- **Descent (75–105 s)** uses a smootherstep depth profile, so vertical speed, pitch
  and pitch rate all start and end at zero. Horizontal speed stays at 0.8 m/s, which
  is what "maintains its speed" requires.

## 4. Conventions

- **World frame:** North-East-Down (NED). `north`, `east`, `depth`; depth is the
  +z coordinate and is **positive downwards**, so descending means depth increases.
- **Body frame:** x forward (surge), y starboard (sway), z down (heave).
- **Attitude:** stored as a unit quaternion `(w, x, y, z)`; Euler angles follow the
  aerospace z-y-x convention. Yaw 0 = north, +90° = east. Pitch positive = nose up.
- **Accelerometer** measures specific force `R_NB · (a_ned − g_ned)`, so a level,
  stationary vehicle reads `[0, 0, +g]` on body-z.

## 5. Quick start

```bash
# from the repository root
python -m pip install -r simulator/requirements.txt

# generate the dataset and the figures
cd simulator/src
python -m auv_simulator.main
```

Options:

| Flag | Default | Meaning |
|------|---------|---------|
| `--dt` | `0.005` | physics time step in seconds |
| `--seed` | `42` | random seed for all sensor noise |
| `--initial-depth` | `20.0` | starting depth in metres |
| `--export-dir` | `exports/` | where the CSV dataset is written |
| `--no-plots` | off | skip figure generation |

Programmatic use:

```python
from auv_simulator import Simulator, Trajectory
from auv_simulator.sensors import Accelerometer, Gyroscope, Magnetometer, PressureSensor
from auv_simulator.state import pressure_to_depth

sim = Simulator(Trajectory(initial_depth=20.0), dt_physics=0.005, seed=42)
sim.add_sensor(Accelerometer(noise_std=0.01, bias=0.005, noise_density=1e-4), 100)
sim.add_sensor(Gyroscope(noise_std=0.002, bias=0.001, noise_density=1e-5), 100)
sim.add_sensor(Magnetometer(noise_std=0.1), 50)
sim.add_sensor(PressureSensor(noise_std=5.0, bias=1.0), 10)

sim.run()
sim.export_ground_truth_csv("exports/ground_truth.csv")
sim.export_sensor_csv("accelerometer", "exports/accelerometer.csv")
```

## 6. Output data contract

All files are CSV with a `t` column in seconds. A navigation filter reads these
files and produces estimates on the same timeline.

**`exports/ground_truth.csv`** — one row per physics tick (24,001 rows at dt = 5 ms).

| Column | Unit | Meaning |
|--------|------|---------|
| `t` | s | simulation time |
| `north` | m | NED north position |
| `east` | m | NED east position |
| `depth` | m | NED down position (positive down) |
| `v_n`, `v_e`, `v_d` | m/s | NED velocity |
| `yaw_rad`, `pitch_rad`, `roll_rad` | rad | z-y-x Euler angles |

**`exports/accelerometer.csv`** — 100 Hz, columns `t, accelerometer_0..2` in m/s²
(body frame, specific force).

**`exports/gyroscope.csv`** — 100 Hz, columns `t, gyroscope_0..2` in rad/s
(body frame `p, q, r`).

**`exports/magnetometer.csv`** — 50 Hz, columns `t, magnetometer_0..2` in µT
(body frame Earth field).

**`exports/pressure.csv`** — 10 Hz, columns `t, pressure_0` in Pa (absolute).
Convert with `pressure_to_depth()` or `(P − 101325) / (ρ g)`, `ρ = 1025 kg/m³`.

Dropped samples are **absent** from a file — never zero-filled.

## 7. Sensor models

| Sensor | Ideal measurement | Reference noise / bias at 100/50/10 Hz |
|--------|-------------------|----------------------------------------|
| Accelerometer | `R_NB · (a_ned − g_ned)` | σ = 0.01 m/s², bias 0.005, drift 1e-4 |
| Gyroscope | body-frame `[p, q, r]` | σ = 0.002 rad/s, bias 0.001, drift 1e-5 |
| Magnetometer | `R_NB · [24, 0, 22] µT` | σ = 0.1 µT |
| Pressure | `101325 + ρ g depth` | σ = 5 Pa, bias 1 Pa |

Every sensor implements:

- `ideal(state)` — the exact physical value, used for validation;
- `read(state, dt)` — the corrupted value, or `None` when the sample dropped.

Error model, applied in this order: mounting misalignment, scale factor, Gaussian
noise, random-walk drift, fixed bias, stuck-at latch, dropout. All terms default to
zero, so a sensor with no arguments is ideal.

Fault injection is available per sensor and is opt-in:

```python
Accelerometer(dropout_prob=0.05)                 # 5 % of samples missing
Gyroscope(stuck_at=[0.0, 0.0, 0.1], fault_start=40.0)
Magnetometer(scale_factor=1.02, misalignment_deg=(0, 0, 2))
```

## 8. Simulation clock

`SimulationClock` owns the timeline. It produces one tick per `dt_physics`, and on
each tick reports which sensors are due:

```python
from auv_simulator import SimulationClock

clock = SimulationClock(duration=120.0, dt_physics=0.005,
                        sensor_periods={"accelerometer": 0.01, "pressure": 0.1})
for tick in clock:
    ...  # tick.t, tick.index, tick.due_sensors
```

Timestamps are always `index * dt_physics`, so ground truth and measurements share
one timeline by construction.
